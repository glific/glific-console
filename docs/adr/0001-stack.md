# ADR 0001: Frontend stack for Glific Console

- Status: accepted
- Date: 2026-11-12

## Context

Glific 2.0 replaces the current MUI + Apollo frontend (glific-frontend) with a redesigned UI. The redesign
prototype (karan26796/glific-redesign) is a visual spec only. Most code will be written with AI assistance and
verified by tests rather than line-by-line review, so the stack must be conventional, well documented, and make
design and quality rules machine-checkable.

## Decisions

| Area                 | Choice                                                                                                | Why                                                                                                                                                                                                                                                                                                                                 |
| -------------------- | ----------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Repo shape           | Single Vite app, pnpm, no monorepo/Turborepo                                                          | One deployable and one team. A monorepo adds workspace config, task graphs and publishing for packages we don't have. If a shared component package is ever needed, extracting `src/components` is straightforward.                                                                                                                 |
| Build                | Vite + React + TypeScript (strict, `noUncheckedIndexedAccess`)                                        | Fast dev loop, standard React setup, strict types catch AI mistakes early.                                                                                                                                                                                                                                                          |
| Components           | shadcn/ui on Radix, Tailwind v4                                                                       | Radix gives accessible behaviour (focus, keyboard, ARIA). shadcn **copies** component source into `src/components/ui` instead of shipping a package: we own the code, can customise it for our tokens, and there is no upstream breaking-change treadmill. The cost is that updates are manual: re-run the CLI and review the diff. |
| Variants             | class-variance-authority                                                                              | Comes with shadcn; typed variant maps are how we extend components instead of forking them.                                                                                                                                                                                                                                         |
| Tokens               | shadcn CSS variables + our semantic additions in `src/styles/tokens.css`, with a TS manifest          | One place for raw values, semantic names everywhere else, light/dark via `.dark`, readable by a future component catalog.                                                                                                                                                                                                           |
| Routing              | React Router (data router)                                                                            | The most widely used React router, nested layouts with error boundaries, and a straightforward route-object API. TanStack Router's typed routes are attractive but add a code-gen/plugin step and a less familiar API for little gain at this size.                                                                                 |
| Server state         | TanStack Query                                                                                        | Caching, retries, loading/error states as data. The backend is GraphQL; the fetch-based `apiClient` can be swapped for a GraphQL client behind the same query hooks.                                                                                                                                                                |
| i18n                 | i18next + react-i18next                                                                               | Same library as glific-frontend, so existing translations and workflows carry over. Typed keys from `en.json`.                                                                                                                                                                                                                      |
| Lint/format          | Biome, with GritQL plugins for design-system rules                                                    | One fast tool instead of ESLint + Prettier; GritQL lets us encode the token/component rules as lint errors with fixture tests.                                                                                                                                                                                                      |
| Unit/component tests | Vitest Browser Mode (Playwright, Chromium) + Testing Library + MSW + axe-core                         | Tests run in a real browser (real focus, layout, CSS tokens), so keyboard and contrast checks are trustworthy.                                                                                                                                                                                                                      |
| E2E                  | Playwright + @axe-core/playwright; visual baselines generated in the official Playwright Docker image | Deterministic screenshots across machines and CI.                                                                                                                                                                                                                                                                                   |
| Workflow             | lefthook, commitlint (Conventional Commits), Changesets, size-limit, Renovate                         | Fast local gates, readable history and changelog, bundle budget, safe dependency updates.                                                                                                                                                                                                                                           |

## Consequences

- Upgrading shadcn components is a deliberate, reviewed step (see AGENTS.md).
- Raw colours, arbitrary Tailwind values, inline styles, Radix imports and ad-hoc controls outside
  `src/components/ui` fail CI; new needs become new tokens, variants or ui components.
- Visual baselines require Docker locally to update.
